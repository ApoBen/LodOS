## GOAL
PC-side half of T026: native/lodos-rootfs Rust crate that extracts rootfs tarballs fast without proot; T026 later wires it into the app and measures on phone.
## STEPS
- Crate native/lodos-rootfs: lib + bin `lodos-rootfs extract <tarball> <dest>`; formats .tar.gz (flate2 w/ zlib-rs backend), .tar.xz (xz2 or lzma-rs), .tar.zst (zstd). Preserve dirs, files, modes, symlinks, mtimes; hardlinks -> copy (or reflink-free copy) and count; skip char/block/fifo devs and record count; never follow symlinks out of dest (path traversal guard: reject `..`/absolute escape).
- Progress callback (bytes in/total) for UI; summary struct {files,dirs,symlinks,hardlinks,skipped_dev,ms}.
- JNI cdylib feature `jni`: `Java_org_lodos_app_setup_NativeRootfs_extract(String src,String dst)` -> returns summary string; exported symbol must exist in aarch64 .so.
- Tests (cargo test, x86_64): build small fixture tarballs in tempdir at test time (tar crate) covering symlink, hardlink, fifo, `../evil` traversal (must be rejected), modes 0755/0644; one bench test (ignored by default) on the real trixie tarball if present via scripts/fetch-rootfs.sh cache.
- Print timing of extracting real rootfs on PC in NOTES if tarball cached.
