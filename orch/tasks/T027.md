## GOAL
Extend guest ICD (T023) from query-only to real work: buffers/memory/cmdbufs/queues/sync/shaders/pipelines/renderpass, so a guest glibc Vulkan app executes on Mali and results read back correctly. No WSI yet.
## STEPS
- Add to cmds_icd.txt + gen/rpcgen the device-level cmds needed (memory alloc/map/flush/invalidate, buffer/image/view, cmdpool/cmdbuf record+submit, fence/semaphore, shader module, descriptor set layout/pool/sets/update, pipeline layout, compute+graphics pipeline, renderpass/framebuffer or dynamic rendering, copy image->buffer).
- Mapped memory: host shm/memfd shared between server and ICD (AHB or memfd-backed import on server side); vkMapMemory returns guest pointer into shared mapping; flush/invalidate sync ranges. Document approach.
- Command buffers: batch vkCmd* into one message per submit (do NOT roundtrip per vkCmd*).
- Test progs in guest (C, built in guest with gcc + glslang/glslc precompiled SPIR-V embedded): (a) compute: add 1M floats, verify; (b) render 256x256 RGBA red triangle on blue clear, readback, check center pixel red + corner blue.
- scripts/guest-vkwork-test.sh: builds/pushes, starts server, runs both; prints `VKB compute ok n=<N> ms=<t>`, `VKB triangle ok center=<rgba> corner=<rgba>`, bridge call count.
## OUTPUT
native/vk-bridge/* updates, native/vk-bridge/test/{compute.c,triangle.c}, scripts/guest-vkwork-test.sh, NOTES with mapped-memory design + remaining gaps for vkcube/zink.
