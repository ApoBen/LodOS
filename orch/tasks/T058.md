## GOAL
Today every vkCmd* is a separate bridge RPC (see native/vk-bridge/NOTES.md). Record vkCmd* client-side into a per-command-buffer byte stream and send it as ONE message (at vkEndCommandBuffer, or flushed at vkQueueSubmit); server decodes and replays on the real cmdbuf. Big perf win for zink/games.
## STEPS
- Generator (native/vk-bridge/gen, rpcgen): emit encode-only (no reply) path for all vkCmd* (void return); server replay loop over the stream. Handles/pointers already marshalled by existing structs code — reuse.
- Client ICD: per-VkCommandBuffer growable buffer; vkBeginCommandBuffer resets; vkEnd flushes as one "cmd_stream" RPC. Keep env VKB_NO_BATCH=1 fallback to old per-call path.
- Count bridge calls: host_triangle/host_compute already print calls=N; batching must reduce it.
- Do NOT touch WSI code paths beyond what's needed to compile.
## OUTPUT
gen/client/server changes; NOTES.md section "cmd batching"; host_triangle.sh prints `calls=N` for both modes, e.g. a line `VKB batch calls batched=<a> unbatched=<b>`.
