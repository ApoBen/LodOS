## STEPS

2. Ensure phoc starts Xwayland (phoc.ini `[core] xwayland=true`, DISPLAY exported to session; check phoc built with xwayland in Debian).

## REVIEW (review30) — task reset, new approach
5 attempts failed at "could not find this guest's Xwayland display/auth arguments". Likely root cause: wlroots/phoc starts Xwayland LAZILY. It only listens on /tmp/.X11-unix/X<N> and spawns the Xwayland process when the first X client connects, so scanning argv finds nothing. Also wlroots does not use an -auth cookie.
New plan (delete the /proc argv-scan block in scripts/pc-desktop.sh ~L181-223):
1. Get DISPLAY from phosh's environment. phoc exports DISPLAY to its children. On the HOST, find the phosh pid that descends from this session's proot/bwrap pid (walk ppid) and read DISPLAY= from /proc/<pid>/environ. Fallback: diff the "$RFS/tmp/.X11-unix/" listing before and after phoc starts.
2. Launch xterm in the guest with DISPLAY=:N and NO XAUTHORITY. Connecting triggers the lazy Xwayland spawn. Allow up to 20s for the first map.
3. If phoc's Xwayland still fails, fallback: in the guest, run `Xwayland :77 -rootless -noreset` as a plain client of phoc's socket, then DISPLAY=:77 xterm. Log which path was used.
Keep the red xterm, the toplevel check, the PNG, and the clean shutdown. Do not add python3 to the guest.
