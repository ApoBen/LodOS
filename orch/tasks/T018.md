## GOAL
First real cross-process Vulkan call: client process encodes cmds (gen.py), sends over T015 transport, server process executes on real Mali driver and replies. Both bionic static/dynamic on phone via adb (/data/local/tmp) for now.
## STEPS
- Extend native/vk-bridge/gen/gen.py: reply direction (out params + VkResult), handle map (server keeps table, client sees u64 ids), array-count two-call idiom, bounds checks on decode. pNext: reject non-NULL with VK_ERROR_FEATURE_NOT_PRESENT for now.
- Commands: vkEnumerateInstanceVersion, vkCreateInstance, vkEnumeratePhysicalDevices, vkGetPhysicalDeviceProperties, vkGetPhysicalDeviceQueueFamilyProperties, vkDestroyInstance.
- native/vk-bridge/server/: listens on abstract socket @lodos-vk (cf R13), per-client thread, dlopen system libvulkan.so (keep path pluggable for vk-layer later), decode->call->encode reply over ring.
- native/vk-bridge/client/: libvkbridge_client (plain C API, not yet an ICD) + test/e2e_test.c: calls the 6 cmds and prints `E2E device=<deviceName> api=<maj.min.patch> qfam=<n>`, then `E2E ok`.
- native/vk-bridge/build-e2e.sh: NDK r30 aarch64 build, adb push, start server bg, run client, kill server, print outputs.
## OUTPUT
gen.py changes, server/, client/, test/e2e_test.c, build-e2e.sh. NOTES: device name, per-call roundtrip latency (avg of 1000 vkGetPhysicalDeviceProperties).
