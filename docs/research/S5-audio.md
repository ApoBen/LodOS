# S5 audio v0 (T049)
- Mechanism: guest PulseAudio 17 (trixie) `module-pipe-sink file=<fifo> format=s16le rate=48000 channels=2 use_system_clock_for_timing=yes` -> guest relay `socat -u OPEN:fifo UNIX-CONNECT:<bound host sock>` -> host `native/lodos-audio` (Rust) unix stream server (`LODOS_AUDIO_SOCK`, sequential clients, reconnects reuse backend) -> Backend trait (`open/write/close`): WavBackend (PC test), AAudioBackend (feature `android`, ndk 0.9 audio, LowLatency, blocking I16 write).
- Wire format: raw S16LE interleaved, fixed 48k/2ch, no header; partial frames carried across reads, dropped at EOF.
- Why not module-simple-protocol-unix: it *listens* (pulse=server, host would have to connect into guest and record from a monitor); pipe-sink pushes, so the host stays the server (fits Android: app owns the socket in filesDir, R13 app uid can bind path AF_UNIX). Relay could become a tiny guest-side static binary instead of socat later.
- Pacing: without `use_system_clock_for_timing` pipe-sink writes as fast as the reader consumes (unbounded silence). `module-suspend-on-idle` stops writes when idle (battery: no host wakeups while silent).
- Latency estimate: FIFO 64 KiB = 341 ms worst case if reader stalls; steady-state = pulse sink latency (pipe-sink default ~ tens of ms, tune via `tsched`/fragment & smaller pipe via F_SETPIPE_SZ) + socket buffer (~a few ms) + AAudio LowLatency (~10-20 ms on Mali/MTK-class phones) => ~50-100 ms target; good for desktop/video, not for rhythm games.
- PC test: `scripts/pc-audio-test.sh` (proot guest, 2 s 440 Hz sox tone via paplay) -> build/T049.wav (leading idle silence trimmed by `LODOS_AUDIO_WAV_TRIM=1`).
- Android integration (T054): `scripts/stage-jnilibs.sh` and Gradle `preBuild` build the `android` feature with cargo-ndk and package the executable as `lib/arm64-v8a/liblodos_audio.so`. `GuestSessionService` starts it before proot with the AAudio backend and socket `<filesDir>/run/audio.sock`; `GuestLaunch` binds it at `/run/lodos/audio.sock`. Guest `PULSE_SERVER=unix:/run/lodos/pulse/native.sock`; `scripts/guest/pulse-lodos.pa` configures the pipe sink, while `scripts/guest/audio-start.sh` starts PulseAudio and relays its FIFO with socat. The service stops the daemon after the guest exits. Phone playback is not yet verified. - Mic later: reverse path: AAudio input -> socket -> guest `module-pipe-source` FIFO (needs RECORD_AUDIO runtime perm).
- Pipewire later (D19): pipewire-pulse supports `module-pipe-sink` compat; same host daemon.
